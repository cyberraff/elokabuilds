# 1. Purpose & Background

Raphael Ejeogo is a freelance web developer running a cold-outreach client acquisition system (internally referred to as the “Silent Contractor” model): identifying local businesses with underperforming websites, pre-building a working demo without prior contact, and pitching the finished product directly to the business owner.

This model is highly effective for conversion, but it introduces a credibility gap. Outreach is unsolicited, often cross-border (Nigeria-based developer contacting businesses in the US, UK, Australia, and across Africa), and arrives without the kind of context a referral or inbound lead would have. Recipients have no way to verify who they're dealing with.

This website exists to close that gap. It is simultaneously:

- A personal portfolio — proof of skill, real work, real identity.

- A trust anchor — referenced in cold emails and Loom videos so prospects can verify Raphael is a real, accountable, contactable professional.

- A lead capture and booking funnel — for inbound interest generated by outreach, referrals, or future organic discovery.

# 2. Goals & Success Metrics

## 2.1 Primary Goals

1. Establish verifiable identity and credibility within 5 seconds of landing on the page.

2. Convert cold-outreach recipients who click through into booked discovery calls.

3. Serve as a living portfolio that can be updated as real client work replaces placeholder case studies.

4. Support the outreach funnel — every cold email, Loom video, and follow-up should be able to link here without friction.

## 2.2 Success Metrics (V1)

| **Metric** | **Target** | **Notes** |
| --- | --- | --- |
| Email-to-site click-through rate | > 15% | % of cold email recipients who visit the site |
| Site visit → Calendly booking rate | > 8% | Primary conversion event |
| Avg. time on page (home) | > 45 sec | Proxy for credibility read-through |
| Bounce rate | < 55% | Especially from mobile, since most opens are mobile |
| Page load (mobile, PageSpeed) | 90+ | Must outperform the very sites being pitched against |

*Note: PageSpeed score is non-negotiable above all other metrics. Pitching low-performing websites while running one yourself is a credibility risk in itself.*

# 3. Target Audience

## 3.1 Primary: Cold Outreach Recipients

Small business owners (healthcare, legal/professional services, trades, hospitality, retail, education) in the US, UK, Australia, Nigeria, Ghana, and Kenya who received a cold email or Loom video and are checking out the sender before responding. Likely skeptical, time-poor, on mobile, possibly suspicious of unsolicited outreach from an unfamiliar (and possibly Nigerian) sender.

## 3.2 Secondary: Referral / Word-of-Mouth Visitors

People referred by a past or current client. Lower skepticism, but still evaluating fit and looking for proof of past work.

## 3.3 Tertiary: Organic / Future Search Visitors

Longer-term audience as SEO and reputation build. Not a V1 priority but the architecture should not preclude this.

# 4. The Trust Problem (Why This Site Exists)

This section exists to keep every later design and content decision anchored to the actual problem being solved.

## 4.1 What triggers scam-perception in cold outreach

- Mismatched sender identity (e.g., generic email domain, no verifiable name)

- No way to confirm the sender is a real, locatable, accountable person

- Generic, non-specific outreach copy

- Requests for payment or information before any value is demonstrated

- Urgency or pressure language

## 4.2 How this site counters each signal

| **Trust Signal Needed** | **Site Element That Delivers It** |
| --- | --- |
| Real, verifiable identity | Full name, real photo, consistent identity matching email signature & LinkedIn |
| Proof of capability | Case studies / portfolio work, even if framed as placeholders initially |
| Accountability / locatability | Clear contact path, professional email tied to custom domain, social proof |
| No-pressure engagement | Calendly booking (no payment ever requested pre-engagement), free-audit framing |
| Professional infrastructure | Custom domain, fast/clean site that itself proves competence |

# 5. Site Architecture & Sitemap

Single-page scrolling architecture for V1, with anchor navigation. This is intentional: cold outreach recipients are time-poor and on mobile — minimizing clicks-to-trust is the priority over a multi-page architecture.

## 5.1 Sitemap

- **Home (/) — single scrolling page containing:**

  - Hero / Introduction

  - About / Credibility

  - Services

  - Work / Case Studies

  - Process / How I Work

  - Contact / Book a Call

  - Footer

- **/work/[slug] — individual case study detail pages (linked from Work section)**

*Future (not V1): /blog for SEO content, /resources for downloadable audit guides.*

# 6. Page-by-Page Requirements

## 6.1 Hero / Introduction

Purpose: confirm within seconds that this is a real, capable person — not a templated scam page.

- Full name displayed prominently: Raphael Ejeogo

- Real, professional photo (not a stock or AI-generated avatar — authenticity is the entire point)

- Clear role/positioning statement (e.g., “Web Developer helping local businesses convert visitors into customers”)

- Primary CTA: “Book a free audit call” → Calendly

- Secondary CTA: “See my work” → scrolls to case studies

- Subtle credibility markers visible without scrolling: e.g., years of experience, number of sites shipped, or location

## 6.2 About / Credibility

- Short bio in first person — written like a real person talking, not corporate copy

- Explicit mention of where Raphael is based — transparency beats vagueness (per outreach trust strategy)

- Mention of working with international/remote clients if relevant, to pre-empt the cross-border question

- Link to LinkedIn (must match name/photo exactly for cross-verification)

- Optional: short personal note on why he does this work (humanizes, differentiates from generic agencies)

## 6.3 Services

- 3–4 clear service offerings (e.g., Website Audit, Website Rebuild, Ongoing Maintenance/Retainer)

- Plain-language descriptions — avoid jargon, the audience is small business owners, not developers

- Explicit “no cost until you're happy” / “free demo first” framing somewhere in this section — this is the single biggest scam-perception killer available

## 6.4 Work / Case Studies

V1 uses placeholder case study cards pulling from Raphael's pre-Silent-Contractor portfolio work. Structure must be ready to swap in live Silent Contractor client results as they close.

- Grid or list of 3–6 project cards

- Each card: project name/business type, one-line outcome, thumbnail image, “View case study” link

- Case study detail view per Appendix B template

- If using fully placeholder/dummy content, label clearly enough to avoid misrepresentation (e.g., real past projects, not fabricated client results)

## 6.5 Process / How I Work

This section directly supports the Silent Contractor pitch by previewing the audit-first, demo-first approach — so when a prospect receives a Loom video, the website corroborates the same process.

1. Free audit — I review your current site's speed, design, and mobile experience

2. Demo build — I build a working preview, often before we've even spoken

3. Walkthrough call — we go through it together, no pressure

4. Launch — only once you're happy, we go live

## 6.6 Contact / Book a Call

- Embedded Calendly widget (primary path)

- Fallback contact form (name, email, business name, message) for those who want to message before booking

- Direct professional email address displayed as text (not just a form) — visible contact info is itself a trust signal

- Optional: links to social proof (LinkedIn, GitHub if relevant)

## 6.7 Footer

- Name, email, location (city/country level)

- Social links

- Simple copyright line

- Optional: privacy note for contact form data

# 7. Design Direction & Brand Brief

Reference inspiration: pelumi.site (dark, minimal, code/engineer-forward developer portfolio). Direction for this build sits between that aesthetic and a warmer, more approachable feel — since part of the audience is non-technical small business owners, not just engineering peers.

## 7.1 Visual Tone

| **Attribute** | **Direction** |
| --- | --- |
| Overall mood | Confident, modern, slightly technical — not cold or sterile |
| Color palette | Dark or near-dark base (per pelumi.site reference) with one warm accent color to avoid feeling purely “engineer flex” |
| Typography | Clean sans-serif for body (e.g., Inter, Geist); optional monospace accents for technical credibility (code-style labels, small UI flourishes) |
| Imagery | Real photo of Raphael required in hero/about. Avoid generic stock photography elsewhere. |
| Motion | Subtle, purposeful micro-interactions only. Avoid heavy animation that could hurt mobile performance/PageSpeed score. |
| Density | Generous whitespace; this is a credibility document as much as a portfolio — it should not feel cluttered or templated. |

## 7.2 Non-Negotiables

- Must be fast. This site is implicitly a proof-of-work for a business built on fixing slow sites — a poor PageSpeed score here undermines the entire pitch.

- Must be fully responsive and mobile-first — most cold-outreach recipients will open links on a phone.

- Must not look like a generic template or page-builder export. Specificity and personal touches matter more here than for a typical portfolio.

# 9. Technical Requirements & Stack

## 9.1 Recommended Stack

- Framework: Astro or Next.js — consistent with stack already used for Silent Contractor client demo builds, keeping tooling familiar

- Styling: Tailwind CSS

- Hosting: Vercel (free tier, already in use for client demos)

- Domain: Custom domain via Namecheap (e.g., raphaelejeogo.com or similar), shared infrastructure with Zoho Mail setup

- Forms: Formspree, Resend, or native serverless function — no backend/database needed for V1

- Scheduling: Calendly embed (free tier sufficient for V1)

## 9.2 Performance Requirements

- Mobile PageSpeed score: 90+ (this is the standard being sold to clients — must hold itself to it)

- Image optimization: all images served in modern formats (WebP/AVIF) with responsive sizing

- No render-blocking third-party scripts above the fold

## 9.3 Accessibility

- Semantic HTML, sufficient color contrast (especially given dark theme direction), alt text on all images, keyboard-navigable

# 15. Appendix A — Domain & Email Setup Guide

This setup directly supports both the website and the broader Silent Contractor outreach credibility strategy (Hunter.io access, professional sender identity).

## A.1 Domain

1. Register domain via Namecheap (e.g., raphaelejeogo.com, or a close variant if unavailable)

2. Point DNS to hosting provider (Vercel) per their documentation

3. Set up DNS records for email (MX, SPF, DKIM) per Zoho Mail's setup guide

## A.2 Email

1. Create professional address: e.g., raphael@raphaelejeogo.com or hello@raphaelejeogo.com

2. Configure SPF, DKIM, and DMARC records — critical for cold email deliverability and avoiding spam flags

3. Test send/receive from the new address before using it in any outreach

4. Use this same domain consistently across email, Calendly, Stripe, and the website — consistency across touchpoints is itself a trust signal

# 16. Appendix B — Case Study Placeholder Template

Use this structure for each older portfolio project being repurposed as a placeholder case study. Keep claims accurate to what was actually delivered — do not fabricate metrics or outcomes.

| **Field** | **Guidance** |
| --- | --- |
| Project name / Client | Real name if permitted, otherwise generic descriptor (e.g., “Local Law Firm Rebuild”) |
| Industry/category | e.g., Hospitality, Legal, Retail |
| The problem | 1–2 sentences on what was wrong with the starting point |
| What was built | 1–2 sentences, plain language, on the solution |
| Outcome | Only include metrics that are real and verifiable. If no hard metrics exist, describe qualitative outcome (e.g., “faster load time, cleaner mobile experience”) |
| Visuals | Before/after screenshots if available; otherwise final-result screenshots only |
| Tech used | Optional, small detail for technically-minded visitors |

# 17. Appendix C — Calendly & Lead Capture Setup

## C.1 Calendly

- Create free Calendly account using the professional email address

- Set up a single “Free Website Audit Call” event type, 15–20 minutes

- Set realistic availability windows accounting for time zone differences across US/UK/Australia/Africa prospects

- Add a short pre-call question (e.g., “What's your website URL?”) to arrive prepared and reduce no-shows

## C.2 Contact Form

- Fields: Name, Email, Business Name, Message (optional)

- Connect to a lightweight form backend (Formspree, Resend, or a simple serverless function) — avoid adding a full backend/database for this

- Auto-reply confirming receipt, to reassure the sender it reached a real person

- Forward submissions to the same professional inbox used for outreach, for a single unified pipeline
